# Agent instructions

Read README.md, ARCHITECTURE.md, examples/THOUGHT.md and SOURCE.md first.

- This is a candidate protocol design. Current scope is documentation; do not
  start implementation, live Agent trials or deployment without operator direction.
- Preserve four primitives: Work, Participant, Act, Relation. Evidence is a
  layer across them. Do not introduce a universal human-first, alternating-turn,
  fixed-round or final-synthesis requirement.
- Separate artist framing, curator authorization, Agent participation and
  infrastructure assertions. Agent intention must have consequential room;
  an authenticated tool call alone does not establish intentional participation.
- Name claims, supporting material, sources, trust dependencies and limits.
  Credentials/signatures do not prove model authorship, private intention or
  freedom from host/curator intervention. Do not use a blanket genuineness flag.
- Qualify actual client/runtime paths before claiming support. A copied prompt,
  browser simulation or fixture is not a working curator-to-real-Agent path.
- Keep artwork-specific rules and implementation with their owners. The Lab
  owns research/publication; this repository owns the protocol candidate.
- Preserve source attribution and immutable historical references. Do not
  rewrite earlier evidence into stronger findings.
- No secrets, private transcripts, private artwork or machine-specific paths.
  Keep Markdown UTF-8, LF, no BOM. Check local links and git diff --check;
  inspect staged changes and run a redacted secret scan before publication.
- After the initial repository bootstrap, work on feature branches. Do not
  publish, change visibility, select licensing or deploy without operator direction.
- Keep replies direct. State what is candidate, unresolved and actually checked.
