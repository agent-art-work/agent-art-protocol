## Application seam and limits

`createSignaturesService` accepts an optional **trusted** `authorizeCopy(request,
signal)` port. It is absent from the local CLI and normal HTTP/MCP transport.
Copy operations are application-only: `commissionAccountCopy`, `collectAccount`
and `cancelAccountCopy`, using a curator credential. Entry/approval/native
inspection alone are insufficient. The synthetic permission port is fixture
authority, not evidence of actual informed Human consent.

Each commission fixes the exact Manifest/omissions, principal/source, recipient
and deadline (at most 60 seconds, clipped by entry/credential/inspection limits).
Its request ID cannot be reused for changed arguments or extend its deadline.
The trusted port must authorize the same commission at begin, before/after each
read and final release; release includes the actual assembled account DataRef.
One bound session uses only native selected inspection, never administrative
reads. Sixteen in-memory commissions and one active collection job bound this
local seam; it has no background scheduler, second ledger or automatic renewal.

The companion bounds inspection to at most 25 reads, 16 records/eight data entries,
60 supplied seconds and 4 MiB cumulative responses. The app additionally supplies
a real-time abort deadline. A callback that ignores cancellation is still pending:
the app reports it and refuses owner closure rather than pretending it stopped.
The implemented cases settle those callbacks before cleanup. Real host/operator
shutdown and permission-port qualification remain open.

Native source rights are checked through the final read; app copy permission is
checked at release. App-controlled withdrawal cancels its pending delivery.
Arbitrary outside-native withdrawal after the last read is not atomically detected
by a separate allow gate. No delivered copy can be retracted by lease expiry.
No source/model authorship, artistic acceptance, independent Report truth or
observed audience display is established by these checks.

Actual private-copy framing, recipient/retention and browser/host delivery need a
separately selected scope. Production provider/session, durable availability and
[supported SDK backup/restore](SDK-RECOVERY-GAP.md) remain gates. Public gallery
work stays off. The public site, Tim walkthrough, renderer and unrelated OPS
changes are preserved; no commit, push, live connection or deployment was made.
