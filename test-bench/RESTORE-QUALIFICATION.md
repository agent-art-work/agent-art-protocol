## Guard changes and reusable candidate scope

The following are local bench facilities, separate from the reading SDK:

- `--focus-recovery` selects a hash-bound **focus-recovery** diagnostic purpose:
  one focus, zero types, clears, host input, handoffs and Sends. It can use the
  already selected explicit 60-second public no-Send capture profile. Historical
  contract bytes and the 30-second default remain unchanged.
- `pause-for-restore` requires an observed, returned focus in that reduced
  scope. It records the original contract/deadline/claim and qualification,
  interrupts readiness, closes its transport and keeps the host case active.
  It supplies no new input or attempt budget.
- Explicit `--recover-case` reconciliation binds a new runtime to the same
  controller and host journal. `inspect-restored-unqualified` checks that no
  current qualification exists and the old generation is rejected, with
  unchanged contract, deadline and focus claim.
- `observe-restored-readiness` requires a fresh actual reviewed empty Chat
  capture after new qualification. `verify-consumed-focus` then checks the
  original host claim guard using that current material and a fail-closed
  callback that cannot dispatch native input. It must reject with `EEXIST`
  before entering that callback. This is a host guard audit, not a repeated
  native focus attempt.
- A superseded controller cannot finalize the recovered case. Uncertain input,
  expired captures or recovery never renew a claim. The full marker-gate pass
  cannot be inferred from this focus-only recovery audit.
- `--setup-profile claude-file-new-chat-v1` separately permits one unique File
  header beneath the actual native menu bar, only from an owned empty composer.
  It retains zero typing, keypress, clearing, handoff and Send scope. The
  historical setup profile cannot open menus. It supplies no arbitrary menu
  command/index API, and the missing-pixels menu route is not qualified.
- A scoped **New session** heading or **Project or folder** popup now rejects
  ordinary Chat readiness as ambiguous. The same words in unrelated sidebar
  content do not define the owned target. This prevents the generic `/new` plus
  Claude-radio check from falsely qualifying the actually observed surface.
